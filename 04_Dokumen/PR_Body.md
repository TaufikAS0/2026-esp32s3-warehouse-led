Adds an ESP32-S3 warehouse location indicator controlled by stable box IDs. One controller drives four WS2812B outputs, supporting 25 three-LED boxes per rack; initial configuration enables one box for staged bring-up.

Includes an embedded slate/cyan dashboard with100 box positions, per-box popup mapping/color/manual controls, separate rack LED settings, saved color indicators, and running/blink/rainbow/breathe hardware-test or continuous idle programs. Active manual commands take priority over animations. Also includes per-rack installed-LED tests, validated mapping drafts, open LAN HTTP API as explicitly requested, bounded timers, NVS configuration, STA/AP recovery, opt-in OTA, and a Python client without write retries. Version is v0.6.0. The user-approved internal AP default is12345678; actual router/API/OTA credentials stay private.

The LED driver uses parameterized NeoPixel constructors to initialize ESP32 IDF5's shared RMT mutex. Empty construction followed by setters previously allowed API success without any LED output. A regression test links the actual pinned NeoPixel implementation and reproduces that failure, then verifies initialization and transmitted frame bytes with GPIO/RMT boundary shims.

Validation: ESP32-S3 compile, C++ domain/driver/codec/animation,11 Python tests and embedded HTML/JS DOM suite pass. v0.6.0 device HTTP tests cover all four programs, expiry/continuous idle, brightness clamp, manual priority, cancellation and invalid input. Chrome verified the popup, saved B02 color after reload and running controls. Authenticated OTA succeeded; reboot retained25-box mapping/Wi-Fi, closed OTA and served HTML matched source. Three GPIO4 LEDs were physically confirmed with v0.5.1. See04_Dokumen/Test_Report.md for evidence and limits.

No active JARVIS source changes. Full optical RGB,75/300 LED/RMT behavior, power distribution, full network recovery and8-hour endurance remain open; this PR is a staged firmware baseline, not a production certification.
