Adds an ESP32-S3 warehouse location indicator controlled by stable box IDs. One controller drives four WS2812B outputs, supporting 25 three-LED boxes per rack; initial configuration enables one box for staged bring-up.

Includes an embedded slate/cyan rack dashboard with100 visible positions, direct per-box mapping editor for all slots, per-rack installed-LED hardware tests, firmware version visible before API connection, selected-box control,3-second RGB/blink tests, per-LED setup presets, validated mapping drafts, open LAN HTTP API as explicitly requested by the user, bounded timers, NVS configuration, STA/AP recovery, opt-in OTA, and a Python client without write retries. Version is v0.5.1. User-approved internal AP default is12345678; actual router/API/OTA credentials stay private.

The LED driver uses parameterized NeoPixel constructors to initialize ESP32 IDF5's shared RMT mutex. Empty construction followed by setters previously allowed API success without any LED output. A regression test links the actual pinned NeoPixel implementation and reproduces that failure, then verifies initialization and transmitted frame bytes with GPIO/RMT boundary shims.

Validation: ESP32-S3 compile, C++ domain/driver/codec,11 Python tests and embedded HTML/JS DOM suite pass. v0.5.1 device tests cover open HTTP, installed-LED rack tests, global brightness limit, RGB/blink, expiry, cancellation and invalid input. Chrome verified the new version and manual box control. Authenticated OTA succeeded; reboot retained mapping/Wi-Fi, closed OTA and served HTML matched source. The user confirmed all three GPIO4 LEDs physically lit green after the fix. See04_Dokumen/Test_Report.md for evidence and limits.

No active JARVIS source changes. Full optical RGB,75/300 LED/RMT behavior, power distribution, full network recovery and8-hour endurance remain open; this PR is a staged firmware baseline, not a production certification.
